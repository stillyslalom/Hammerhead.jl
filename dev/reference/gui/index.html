Graphical user interface (GUI; HammerheadGUI)

The desktop GUI uses GLMakie. The application and view functions below open interactive tools; HammerheadGUI.Controllers holds their state and actions for scripted use without a display. Start with the GUI tour for a worked session. Result browsing, interactive analysis and recorded processing details have a separate result explorer reference. Saved-recipe controls and views have their own experiment workflow reference. Resumable processing has a separate checkpoint workflow reference.

Application and views

HammerheadGUI.HammerheadGUI — Module
HammerheadGUI

GLMakie views and controllers for inspecting and running Hammerhead analyses. Use the views for interactive work, or use Controllers to configure and inspect an analysis without opening a window. Controller state is exposed through Observables.

source
HammerheadGUI.mask_editor — Method
mask_editor(source; size = (1000, 700)) -> Figure

Open the mask editor on an image matrix, an image-file path, or a prebuilt MaskEditor. Pass the controller to read the edited mask with polygon_mask(editor) or to seed polygons before opening the view.

Editing model: left-click adds vertices (on empty background it starts a new polygon; inside an existing polygon it selects it), right-click closes the active polygon, Backspace undoes the last vertex, Delete removes the selected polygon. "Save mask…" writes a grayscale image in which white pixels are excluded; Hammerhead.load_mask can read it back.

source
HammerheadGUI.preprocess_preview! — Method
preprocess_preview!(target, pp::PreprocessPreview) -> GridLayout

Build the preview in a GridPosition and return its GridLayout for embedding in a larger figure.

source
HammerheadGUI.preprocess_preview — Method
preprocess_preview(source; size = (1200, 640)) -> Figure

Preview preprocessing on a representative image or a prebuilt PreprocessPreview. The raw and processed images appear side by side. Use the step toggles and parameter fields to compare results; "▲" moves a step earlier in the pipeline. "Background…" chooses frames for a background-subtraction reference. Pass the selected pipeline to a batch with build_preprocess or set_preprocess!.

When the controller carries a pair frame (set_pair!), clicking the processed image places a single-window correlation probe: the window outline is drawn at the click, and the panel below reports its displacement and peak ratio as steps change. Repeat the probe at several locations before applying the pipeline to a sequence.

roi_editor!(position, editor::ROIEditor; batch = nothing)

Embed the ROI editor in a figure's GridPosition. Mouse gestures are forwarded to the framework-free controller; the image stays in original pixel coordinates (x = column, y = row).

source
HammerheadGUI.roi_editor — Method
roi_editor(image_or_controller; batch = nothing, size = (900, 560)) -> Figure

Open a rectangular ROI editor. Click two opposite corners or edit the four inclusive pixel bounds and press "set bounds". "Full image" resets the selection. Pass batch = bc to apply the completed selection to a planar BatchRunner. Errors appear below the form.

source
HammerheadGUI.batch_runner — Method
batch_runner(bc = BatchRunner(); size = (960, 720)) -> Figure

Open the planar PIV batch form. Add frames, choose a pairing mode, set the window schedule and processing options, then run. An optional mask excludes image regions. "Edit ROI" opens a rectangle editor on the first frame; "full image" resets the batch selection. An output path writes completed pairs to JLD2 as the run progresses. "Cancel" stops after the current pair. "View results" opens result_explorer after the first pair finishes; later pairs appear there as they complete. "Saved experiments" opens the dedicated recipe workflow to snapshot these settings or reopen a saved experiment without narrowing its settings to this form. "Saved ensemble" opens the separate full-image pooled workflow. Its explicit CPU/KA and precision choices apply to the next snapshot; ROI/custom scripts refuse.

Pass a prebuilt BatchRunner to supply in-memory frames or control the run programmatically.

source
HammerheadGUI.scale_tool — Method
scale_tool(source; batch = nothing, size = (900, 560)) -> Figure

Open the calibration-line scale tool on source: an image (matrix or path) or a prebuilt ScaleTool controller. Click the two endpoints of a feature of known physical size, enter the separation, units, and frame interval, and the derived pixel size / scale updates live. Pass a BatchRunner as batch to get an "apply to batch" button that copies the scale into its form (apply_scale!).

HammerheadGUI.calibration_review — Method
calibration_review(images, zs; model = :soloff, detect_kwargs...) -> Figure
calibration_review(cr::CalibrationReview) -> Figure

Review detected dots and reprojection errors for each calibration plate. The plane slider selects an image; dots are colored by error in pixels and fiducial markers are outlined in cyan. Changing the camera model between soloff and pinhole refits the camera. detect_kwargs are passed to Hammerhead.detect_calibration_grid.

source
HammerheadGUI.selfcal_review — Method
selfcal_review(report::SelfCalibrationReport; size = (1150, 650)) -> Figure

Open the self-calibration report with per-pass disparity and triangulation statistics, fitted sheet planes, and the cumulative rigid correction. The reported disparity median is a median magnitude, not a signed component. Inspect RMS and the spatial pattern of both disparity components when the report has not converged. Pass keep_disparity_maps = true to self_calibrate to retain the maps; the explorer's frame slider then steps through the passes.

source
HammerheadGUI.stereo_batch_runner — Method
stereo_batch_runner(sbc = StereoBatchRunner(); size = (960, 600)) -> Figure

Open the stereo PIV batch form. Add synchronized frames for both cameras and supply dewarpers from stereo_calibration or set_dewarpers!. Choose an effort preset or manual window schedule, enter the frame interval and units, and run. Stereo displacements are already in world units; the frame interval converts them to velocities. An optional output file stores completed acquisitions incrementally. "Cancel" stops between acquisitions, and "View results" opens an explorer that receives each finished acquisition. "Saved stereo workflow" opens a separate intact-recipe lane for file-based snapshots, saved history and verified replay.

source
HammerheadGUI.stereo_calibration — Method
stereo_calibration(cr1, cr2; batch = nothing, size = (1500, 850)) -> Figure

Open the stereo rig setup: the two cameras' CalibrationReviews embedded side by side (plane sliders, model menus, reprojection errors), the dewarp-grid options (coverage and spacing), and a "build dewarpers" button running build_dewarpers over the two fitted cameras. Pass a StereoBatchRunner as batch to install the built pair directly into its form (set_dewarpers!); without one the figure still reports the built grid in its status line (build programmatically for a REPL hand-off).

Controllers

Controllers hold application state and logic. You can use them without opening a window or creating a GL context.

For planar image selection, ROIEditor edits core ROI bounds and apply_roi! copies them into BatchRunner. set_roi! and clear_roi! also operate directly on a batch controller. The roi_editor! view can be embedded alongside an image or result comparison.

HammerheadGUI.Controllers.MaskEditor — Type
MaskEditor(image; polygons = [])
MaskEditor(path::AbstractString)

Edit an exclusion mask over a reference image (matrix or image path). Editing state is held in Observables: polygons (committed polygons, each a vector of (x, y) vertices in pixel coordinates), active (the in-progress polygon), selected (index of the selected polygon or nothing), and show_mask (overlay toggle).

Gestures (click!, alt_click!) implement the editing model: click to add vertices (a click on empty background starts a new polygon; a click inside an existing polygon selects it), alt/right-click to close the active polygon. Export the combined mask with polygon_mask(editor) or save_mask. Use begin_hole! to draw a region that is restored inside an exclusion polygon. Seed polygons to resume editing an existing set.

HammerheadGUI.Controllers.PreprocStep — Type
PreprocStep(name, enabled, params)

One pipeline entry: a core preprocessing step (name), whether it is applied (enabled), and its numeric parameters (params, a Dict{Symbol,Float64}). Built by PreprocessPreview; mutate through enable_step!, set_step_param!, and move_step! so the preview refreshes.

HammerheadGUI.Controllers.PreprocessPreview — Type
PreprocessPreview(image; pair = nothing, enabled = Symbol[])
PreprocessPreview(path::AbstractString; kwargs...)

Preview an ordered preprocessing pipeline on a representative image (matrix or image path). steps contains all supported steps; only names in enabled run initially. Set a background with set_background! before enabling subtraction. processed updates when image or steps change.

Supported steps, in default order: :subtract_background, :intensity_cap (n_sigma), :highpass_filter (sigma), :clahe (clip_limit), :percentile_stretch (low/high), :invert_image, and :local_variance_normalize (sigma). build_preprocess exports the composed closure for the batch drivers.

With pair (the representative frame's correlation partner — matrix or path, see set_pair!) a single-window correlation probe becomes available: click! places it, probe_window sizes it (64 px by default, set_probe_window!), and probe_result / probe_summary report the window's displacement and peak ratio, recomputed as the pipeline changes. Probe several representative locations before applying a pipeline to a full batch.

HammerheadGUI.Controllers.BatchRunner — Type
BatchRunner(; kwargs...)

Configure a planar PIV sequence and observe its progress. Inputs, options, and run state are Observables.

Keyword defaults

  • files = Any[] (frame paths and/or in-memory matrices), pair_mode = :paired
  • effort = :custom — :custom runs the manual window schedule below; :low / :medium / :high use run_piv_sequence's effort presets and ignore the schedule/option widgets.
  • window_schedule = [64, 32, 32], overlap_fraction = 0.5
  • correlation_method = :cross, padding = true, apodization = :gauss subpixel_method = :gauss3, uncertainty = false
  • pixel_size = 1.0, dt = 1.0, length_unit = "px", time_unit = "frame" — a PhysicalScale is attached to the outputs only when any of these differs from its default.
  • output_path = "" (empty = keep results in memory only), mask = nothing
  • roi = nothing (full image), or a core ROI / (rows, cols) range tuple. Preprocessing receives full frames; the core crops the images and mask, retaining original image coordinates in the results.

Drive it with add_files!, set_schedule!, set_effort!, set_preprocess! (an optional per-frame preprocessing pipeline, e.g. from a PreprocessPreview), start! and cancel!; watch progress ((done, total)), status, running, results (a Vector{PIVResult} after a completed run, nothing before), and completed (finished pairs appended during a run; feed them to a ResultExplorer via push_result! to browse a batch in progress).

HammerheadGUI.Controllers.StereoBatchRunner — Type
StereoBatchRunner(; kwargs...)

Configure a stereo PIV sequence and observe its progress. files1 and files2 hold synchronized camera frames. Supply a pair of ImageDewarpers with set_dewarpers! or build_dewarpers before running. Inputs and run state are Observables. Stereo displacements are already in world units; the dt, time_unit, and length_unit settings determine velocity units.

Keyword defaults

  • files1 = Any[], files2 = Any[], pair_mode = :paired
  • dewarpers = nothing (a (dw1, dw2) tuple sharing one DewarpGrid)
  • effort = :custom, window_schedule = [64, 32, 32], overlap_fraction = 0.5, uncertainty = false (the manual schedule uses padded correlation and Gaussian apodization)
  • dt = 1.0, time_unit = "frame", length_unit = "world units" — a dt-only PhysicalScale is attached when any differs from default
  • output_path = "" (empty = in memory only)

Drive it like a BatchRunner: add_files! (with a camera keyword), set_schedule!, set_effort!, start!, cancel! (the stereo driver's native between-acquisition cancellation — the completed prefix is kept in results); watch progress, status, running, results, and the live completed accumulator.

build_dewarpers(cr1::CalibrationReview, cr2::CalibrationReview;
                z = 0.0, spacing = :auto, coverage = :intersection,
                margin = 0.0) -> (dw1, dw2)

Build a pair of ImageDewarpers on one world-coordinate grid. z selects the world plane; spacing and margin use the calibrations' world length unit. coverage = :intersection or :union combines the cameras' projected boundary boxes, not their exact visible regions; out-of-view samples remain masked per camera.
